## Why use it

**An `.env.example` that tells the next developer where every value comes from.**

- **Use it when:** a project needs a new or better environment template.
- **You get:** a template built from the code that reads each setting, with docs links, dashboard links, and commands beside the values they explain.
- **Limit:** it never reads real env files, and a template that parses does not prove provider credentials work.

Invoke it as `$sams-env` in Codex, `/sams-env` in Claude Code, or `/sams:env` with the collection bundle.

## Upgrade from Env Example

Collection 0.12.0 renames the standalone skill from `env-example` to `sams-env`. Install it with `npx skills add ThatGuySam/skills --skill sams-env`, then replace `$env-example` with `$sams-env` in Codex, `/env-example` with `/sams-env` in standalone Claude Code, or `/sam:env-example` with `/sams:env` in the collection bundle. After verifying the new installation, remove the older `env-example` installation to avoid loading both. Existing installed copies remain until you remove them. Documentation URLs under `/env-example/` remain valid.

The updated skill adds a spacing checker and formatter for newly authored examples. It also asks for setting-specific dashboard links and distinguishes app-owned secrets from provider API tokens. These checks do not verify provider connectivity.
