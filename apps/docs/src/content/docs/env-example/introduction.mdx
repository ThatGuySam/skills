Sam's Env drafts environment templates from a project's actual configuration contract. It puts documentation links, dashboard entry points, and useful commands beside the settings they explain.

Install the standalone skill:

```sh
npx skills add ThatGuySam/skills --skill sams-env
```

## Upgrade from Env Example

Collection 0.12.0 renames the standalone skill from `env-example` to `sams-env`. Install it with `npx skills add ThatGuySam/skills --skill sams-env`, then replace `$env-example` with `$sams-env` in Codex, `/env-example` with `/sams-env` in standalone Claude Code, or `/sam:env-example` with `/sam:sams-env` in the collection bundle. After verifying the new installation, remove the older `env-example` installation to avoid loading both. Existing installed copies remain until you remove them. Documentation URLs under `/env-example/` remain valid.

The updated skill adds a spacing checker and formatter for newly authored examples. It also asks for setting-specific dashboard links and distinguishes app-owned secrets from provider API tokens. These checks do not verify provider connectivity.

## Use

```text
Use $sams-env to draft this project's .env.example from its source and
configuration schema. Include useful docs links, dashboard links, and commands.
```

## Behavior

The skill inspects the loader and configuration consumers, drafts the template, and distinguishes parsing checks from application validation and provider verification. It preserves the difference between missing and empty settings and marks unknown requirements rather than guessing.

## Inputs and Outputs

Input is a repository or explicit configuration contract. Output is an environment template, needed setup-doc changes, and an evidence report. Only Git-tracked `.env.example` files supply existing env content. Code, schemas, and public provider docs supply the rest. Actual env files are never inspected.

## States and Edge Cases

Incomplete contracts produce a draft with explicit gaps. Optional integrations remain optional. Blank required credentials leave application setup incomplete even if the template parses. Loader-specific syntax and public browser prefixes are resolved from the target project.

Read the [research](/research/concise-env-example-writing-2026-10-09/) behind this revision.

## Agent Checker

The skill includes a dependency-free Node.js checker for a documented static subset of `@env-spec`. It checks types, required values, annotation syntax, and duplicates without printing values. See [checker usage](/env-example/checker/).

## Data Shape

Each variable has a name, purpose, requiredness, value format, missing/empty behavior, and exposure. Acquisition links, commands, permissions, and restart rules are added only where relevant.
