# Backup-first workflow validation — 2026-10-01

This candidate extends the existing migration workflow with private source
capture, a file-snapshot helper, standard skill packaging guidance, and explicit
ChatGPT Web installation limits. All new fixtures are synthetic. No actual GPT
was exported, migrated, published, or installed in a user's account.

Backup tests cover byte preservation, source metadata, missing-file status,
owner-only root/file permissions on POSIX, refusal to overwrite, relative path
and symlink rejection, missing captured files, Git working-tree destination
rejection, review/ownership flags, unaccounted files, corruption with and without
Python optimization, duplicate keys/IDs, and malformed/timezone-less timestamps.
An independent code review identified generated bytecode and timestamp/schema
drift; both were fixed before the final checks.

The helper uses Python's standard library. The timestamp check is explicit;
optional JSON Schema date-time dependencies are not required. SHA-256 compares
captured bytes, not completeness, source authenticity, or secret-freedom.

## Reproduction

From the repository root:

```bash
python3 -m unittest discover -s evals/migrate-cgpt -p 'test_*.py'
python3 -O -m unittest discover -s evals/migrate-cgpt -p 'test_*.py'
python3 evals/migrate-cgpt/check.py
python3 -O evals/migrate-cgpt/check.py
node --test apps/docs/src/scripts/*.test.mjs
```

Use the current installed skill-creator validator for every `skills/*` directory.
Validate root `plugin.json` using the schema at its `$schema` URL, and run strict
Claude validation for both `.claude-plugin/marketplace.json` and
`.claude-plugin/plugin.json`. The Codex probe is
`node evals/migrate-cgpt/plugin-read.mjs .`; use a disposable writable `CODEX_HOME`
if the default configuration directory is read-only. The first loader attempt
in this environment could not write its default home; the disposable-home run
passed without installing or invoking the plugin.

For a disposable project install, run:

```bash
npx skills add /absolute/path/to/candidate --skill migrate-cgpt --agent codex --copy --yes
diff -r /absolute/path/to/candidate/skills/migrate-cgpt .agents/skills/migrate-cgpt
```

From `apps/docs`, install using the documented minimum release age, run
`ASTRO_TELEMETRY_DISABLED=1 bun run build`, and invoke the original `docs-spec`
check script with the app's absolute path. In this environment Bun was invoked
through its npm package because no global Bun executable existed; npm caches
and test configuration remained outside the checkout. The original check script
is relocation-safe and was obtained through authorized access, inspected, and
run unmodified outside the public repository. A substitute gate was not used.
No private source provenance is included here.

The build retains existing nonfatal notices for deprecated Markdown options and
a missing custom 404 entry. No lockfile change or documentation deployment was
performed.

## Limits

The new backup helper and packaging were executed, but the revised migration
instructions have not been run end-to-end on a real owned GPT. Original-GPT
parity, live Actions/authentication, hosted migration and its read-only effect,
account-specific Web installation, implicit skill selection, and real knowledge
retrieval remain untested. Follow the hand-test checklist on one owned GPT before
batch use. Earlier recorded response evaluations remain historical evidence for
the previous skill revision; the replay checker is not a new behavioral run.

The requirements digest added to the older run manifest is retrospective. It
protects against later drift, not against alteration before the digest was first
recorded. Likewise, removing private provenance from current files does not
remove it from earlier Git commits; no history rewrite was attempted.
