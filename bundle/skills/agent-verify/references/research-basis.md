# Research basis and design limits

Reviewed October 31, 2026. This skill is an evidence-informed workflow, not a demonstrated guarantee that fresh agents or model escalation improve every result. Recheck model/runtime capabilities when executing; the sources below are methods, not runtime instructions.

| Source | Finding used | Limit and design inference |
| --- | --- | --- |
| [OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) | Task-specific criteria, executable checks, pairwise grading, human calibration and order/verbosity bias matter. The current guide recommends a strong judge before optimizing judging cost. | Terra-first QA is a budget-sensitive pilot, not an equivalent replacement for a calibrated strong judge. Escalate or retain uncertainty when anchors fail. |
| [Anthropic, Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents), Jan 9, 2026 | Actual environment outcomes differ from agent claims; multiple trials and combined check types reveal failures. | Check relevant artifacts and tool events; do not certify actions from a final answer alone. One cheap layer cannot prove every property. |
| [Zheng et al., MT-Bench and Chatbot Arena](https://arxiv.org/abs/2306.05685), 2023 | Studied position, verbosity and self-enhancement bias in model judgments alongside agreement with human preferences. | Randomize/blind labels and check reversed order for material subjective differences. Older-model task results are not Terra/Astra calibration. |
| [Shankar et al., Who Validates the Validators?](https://arxiv.org/html/2404.12272v1), UIST 2024 | The EvalGen study examines aligning generated evaluators with user grades and reports that reviewing outputs refines people's criteria. | Allow exploratory criterion development, then freeze a separate confirmation. Its small practitioner study does not validate a particular grader or set a universal label quota. |
| [Ribeiro et al., CheckList](https://aclanthology.org/2020.acl-main.442.pdf), ACL 2020 | Tests minimum functionality, invariance and directional expectations in three NLP tasks. | Use focused constructed controls to probe specific failures; adapting them to agents is a design inference. Controls do not substitute for representative user tasks or human preference validation. |
| [Panickssery et al., Self-preference](https://arxiv.org/abs/2404.13076), 2024 | Models can recognize and favor their own generations in studied tasks. | A fresh QA conversation reduces author-context leakage but does not erase same-model bias. Independent context is not statistical independence. |
| [Xiong et al., Confidence elicitation](https://arxiv.org/abs/2306.13063), ICLR 2024 | Verbal confidence can be overconfident; studied methods do not uniformly solve difficult-task uncertainty. | Confidence is optional evidence to calibrate, never a universal approval threshold. |
| [Apple, Learning to Route LLMs with Confidence Tokens](https://machinelearning.apple.com/research/learning-to-route), ICML 2025 | A trained confidence-token method improved routing/rejection over conventional confidence signals in the authors' experiments. | This does not establish that asking an unmodified model for a number supplies that signal. |
| [RouteLLM](https://arxiv.org/abs/2406.18665), revised Feb 23, 2025 | Learned routing uses preference data to select stronger/weaker models. | Supports investigating adaptive routing, not a universal Terra-to-Astra threshold or guaranteed transfer. |

The coordinator/worker/fresh-QA/adjudicator separation is our design synthesis. The coordinator retains task ownership and checks evidence; fresh QA supplies the first interpretive verdict. Objective checks can be decisive without another model. A different grader model is useful only if permitted and capable on the rubric; it is not a substitute for labels and artifact verification. Human judgment remains necessary for user values and some domain decisions.

Practical defaults such as one repair, one escalation and small category-based pilots are budgeting choices. Their adequacy must be established for the workload. Improvement evidence must allow no-change and regression outcomes, retain failures, and avoid grading answers against the author's desired conclusion.

## Improvement loop sources

Reviewed November 5, 2026, for the [improvement loop](improvement-loop.md). Sam chose the defaults (ten binary checks, a reproduced ≤6/10 red, and a plateau-or-five-round stop) on that date. The sources support the method; they do not establish those exact constants.

| Source | Finding used | Limit and design inference |
| --- | --- | --- |
| [Husain and Shankar, AI Evals FAQ](https://hamel.dev/blog/posts/evals-faq/) | Binary pass/fail labels are more consistent than Likert scales; track gradual progress as counts of separate binary checks; derive criteria from error analysis. | Supports scoring /10 as a count of checks. It does not validate any particular ten-item checklist. |
| [Shankar et al., Who Validates the Validators?](https://arxiv.org/abs/2404.12272), UIST 2024 | Criteria drift: grading outputs changes the criteria people want. | Run exploratory error analysis before freezing; version the checklist instead of editing it mid-loop. |
| [Simon Willison, Red/green TDD](https://simonwillison.net/guides/agentic-engineering-patterns/red-green-tdd/) | Confirming that a test fails first proves it exercises the change. | Adapted to prompts: a reproduced poor score is the red gate. Prompt outputs are stochastic, hence three trials. |
| [Anthropic, Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), Jan 9, 2026 | Run multiple trials; grade outcomes rather than paths; capability evals graduate to regression suites when saturated; start from 20–50 real failures. | Supports medians over three trials and promoting saturated cases. A small pilot remains a pilot. |
| [Miller, Adding Error Bars to Evals](https://arxiv.org/abs/2411.00640), 2024 | Use paired differences, clustered standard errors, and power analysis. | Small holdout sets cannot support significance claims; report paired per-case changes. |
| [Arize, prompt optimization](https://arize.com/glossary/prompt-optimization/); [Evidently, automated prompt optimization](https://www.evidentlyai.com/blog/automated-prompt-optimization) | Fix the evaluation set, holdout set, and evaluator before revising; select on validation and report on holdout. | Vendor practitioner posts, consistent with standard ML practice. Supports the holdout split hidden from the refactorer. |
| [Hopman and Parent, Prompt optimization for AI control](https://www.lesswrong.com/posts/bALBxf3yGGx4bvvem/prompt-optimization-can-enable-ai-control-research), Sep 2025, with comments | Inspect optimized prompts for overfitting; ablating examples and specific descriptions cost little performance in one commenter's test. | One reported case. Motivates the refactor step's ablation check, not a guaranteed outcome. |
| [OpenAI prompt optimizer guide](https://developers.openai.com/api/docs/guides/prompt-optimizer) | Optimization depends on narrow graders; an optimized prompt can do worse on specific inputs. The dataset-backed optimizer is deprecated with Evals (read-only October 31, shutdown November 30, 2026). | Supports the per-case no-regression keep rule. Do not depend on the retiring tool. |
| [Claude release notes](https://platform.claude.com/docs/en/release-notes/overview), July 17, 2026 | The legacy Workbench and the `improve_prompt` API were retired on August 17, 2026. | Vendor prompt improvers are not a dependency of this loop. |
| [AI Evals skills](https://github.com/ai-evals-course/evals-skills) | Judge validation uses split human labels, TPR/TNR targets, and about 100 labeled examples. | An optional calibration path when labels exist; the loop otherwise relies on the grader controls in [QA roles and grading](qa.md). |
