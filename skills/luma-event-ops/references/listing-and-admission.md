# Listing and Admission

## Draft and Stage the Listing

- Compare the current listing with the requested changes. For each field, capture the observed value, proposed value or paste-ready copy, source, and approval status. Include question types and requiredness. Mark unresolved decisions and fields inaccessible from your view.
- For an authorized new listing, stage confirmed facts on the intended calendar with Private (unlisted) visibility when preparing for a later launch. Public shows the event on the calendar. Member-Only is available on calendars with membership enabled and shows the event on the calendar to active members. Anyone with the direct link can open a Private or Member-Only event. Load reviewed copy into the same event and publish only within the authorized scope. Keep the existing URL for the same event. [Setting your event visibility](https://help.luma.com/p/setting-your-event-visibility)
- Write concrete attendee outcomes and confirmed activities, demos, participation options, affiliations, and applicable conduct terms. State confirmed costs, installation, and device requirements. Flag tentative times in the review and leave the venue field blank while unsettled. Set room capacity when the venue or format is confirmed.
- Confirm the managing calendar, displayed hosts, session facilitator, and venue independently. Adding a co-host can send an invitation. Verify the approved person, access role, and public visibility before adding them and read back the role afterward.
- For a limited interactive room with a public stream, set the interactive meeting link in Virtual Join URL and use a separate confirmed watch link for the public stream. Check what a signed-out visitor sees and what approved guests can access before sharing either link. [Event registration process](https://help.luma.com/p/event-registration-process)
- Reuse the approved cover layout and verify the uploaded image after saving. Keep changeable logistics in the listing or companion material. Confirm any marks used in the artwork.

## Configure Registration and Admission

- When seats are scarce, ask one required free-text question about a real task or use case. Say that a concrete sentence is enough. Use quick choices for experience, participation, contribution, or equipment only when those answers help the organizer plan. Keep concerns optional and add an explicit conduct agreement when required.
- Agree on a rubric and seat-release path before launch. Judge specificity and willingness to participate. Keep employer, credentials, prose polish, word count, and AI-detector scores out of the decision. Options include one short follow-up for a vague answer or an agreed draw across qualified applicants that retains an experience mix. Put confirmed logistics and the seat-release instructions in the approval message.
- Check ticket approval, event capacity, and waitlist settings independently. Review pending applications and people waitlisted for capacity as distinct queues. Native invites can bypass approval, including when forwarded. Use the ordinary event link for people who should apply. Check acceptances against available seats before sending another authorized wave. [Inviting and adding guests](https://help.luma.com/p/inviting-and-adding-guests-to-your-event)
- Decide whether networking warrants showing the guest list. Check what signed-out visitors, approved guests, and hosts can see. [Event guest list](https://help.luma.com/p/event-guest-list)

Promoting or announcing the listing is an external write. Get explicit scope for the destination, audience, content, and timing. Before promoting the listing, read back ticket approval and test the application through the point before submission. If questions were added after registration opened, consider whether existing registrants need a separately authorized follow-up.

## Coordinate Partner Registration

Confirm whether each URL points to this event or to a calendar. Verify claimed organizer or partner affiliations with a current organizer record. Test the exact ticket button or redirect on the partner listing. Use one registration destination where possible. If a partner registers people separately, clarify that both listings describe the same event, ask the partner to mirror essential planning questions, and account for both rosters and any difference in approval when planning capacity. Verify the listing on the intended calendar before reporting that it appears there.
