# Communications and Feedback

## Invitations and Blasts

- Before sending or scheduling an invite or blast, confirm the recipient group, message (including any default wording), and send time for each action. Ask for any missing scope and prepare local drafts while you wait. For past-attendee outreach, use verified check-ins and deduplicate privately. For topic-based outreach, prioritize fit and verified participation. Registration, opens, and join-link clicks are weaker signals. Keep a normal application link for newcomers who need approval.
- Share the direct event link for registration, the group calendar for browsing, or the public watch link for viewing. Test the exact destination, including short links and QR codes.
- Check recent posts, sent blasts, and queued reminders. Give each new message one job. Confirm the **Going** filter in the composer for an attendee-only blast and verify any ticket filters. Send one confirmed address update when needed. Leave routine timing to the scheduled reminders when enabled. [Sending or scheduling event blasts](https://help.luma.com/p/sending-or-scheduling-event-blasts)

## Reschedule the Same Event

1. Read the existing event, original date and time zone, and registration settings. Identify the proposed date, time zone, and any affected notices. Luma may send an automatic calendar update to Going guests when saving a change to the name, time, duration, or venue. Inspect the save prompt or current behavior before applying the change. Include any triggered notification in the authorized scope. [Updating event information](https://help.luma.com/p/updating-event-information)
2. When authorized, update the existing Luma listing first and keep its link. Read back the new time and confirm the registration state and which questions, registrations, and votes carry over before making claims to guests.
3. Reconcile date references in the description, partner listings, queued notices, artwork, and the original community discussion. Handle each external edit within its own authorized scope. Check for the automatic update before planning a manual blast. If a separate message serves a distinct purpose, use one clear, authorized update with the old and new times, time zone, and event link.

## Check-In and Follow-Up

- Assign a check-in owner and a defined check-in path. Use the completed event's check-in records and deduplicate privately. Reconcile dated partner exports if there were two registration paths and preserve question wording when comparing responses. Report attendance separately from registrations, approvals, join-link clicks, and replay views. Flag gaps in check-in coverage.
- Make one feedback request when authorized. Use Luma's native feedback request for a quick rating and tell guests the host can see who submitted the rating or comment. Include one optional anonymous outcome form with sign-in and address collection disabled. The native request goes to Going guests, so match responses to check-ins privately before calculating attendee ratings or response rates. [Collect feedback from your event guests](https://help.luma.com/p/collect-feedback-from-your-event-guests)
- Keep one metrics row per event. Calculate show rate as unique check-ins divided by Going guests and attendee feedback response rate as checked-in respondents divided by unique check-ins. Label export dates and denominators. Mark unavailable counts or zero-denominator rates as unavailable. Track confidence change, intended use, and later self-reported use separately.
- Share the promised slides, replay, and resources in the attendee hub, plus the next event once confirmed. Verify access as the intended viewer and scan transcripts for personal information before sharing. Publish themes or counts and keep identifiable responses in organizer-controlled storage.
