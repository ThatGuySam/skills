# Output Modes

These expanded modes apply only when explicitly requested. The default action-item deliverable is one phone-sized response in the current chat. Apply `phone-size` in every mode. A request to prepare action items alone does not authorize a separate packet or file.

## Personal Queue

Lead with actions the user can advance. Keep waiting-on-others, consequential decisions, and optional ideas separate. A personal view can omit others' actions from the first screen while preserving them in the supporting record. For each visible item, state the concrete next step and any real prerequisite.

## Prepared Follow-Up Packet

Start with what is ready to use and what remains missing. For each action needing preparation, include the resource, draft, choice, or source-retrieval result. Reuse existing material. Create a document only when the user requests one, and include message drafts only when requested. Otherwise provide the prepared resources and next actions within the chat brief.

Keep researched recommendations distinct from what the meeting agreed. If a named video, template, policy, or document cannot be identified, state that limitation and the evidence searched. A candidate substitute should be visibly labeled, with its reason for inclusion. Do not invent a title, URL, date, or attachment contents.

## Team Register and Plan Update

Preserve a stable action ID when a register already exists. Track the outcome, human owner, execution actor where different, source and later correction, existing destination, current disposition, dependency, and completion evidence. Omit unused fields from the visible table rather than filling them with guessed values.

Update scope and dependencies when new evidence changes them. Link related historical tasks instead of reopening completed work. Show the meaningful difference from the previous register, including cancelled or newly covered actions.

## Agent Handoff

Group work by shared context and dependencies rather than opening one task per meeting bullet. Each recipient prompt must independently direct the agent to the relevant original discussion and later corrections. Include the accessible source locator, accepted baseline, changed or remaining outcome, prerequisites, current authority, and an observable completion check.

Check recipient access. A local uncommitted path may be unavailable to a cloud agent or a new worktree. Prepare authorized relevant context or identify the access blocker before dependent execution.

When work requires reconciling ongoing chats, successor routing, dispatch receipts, or repeated follow-up runs, use an installed follow-up or dispatch skill if one is available. Carry the reconciled actions into it; do not repeat extraction or start a competing register. If unavailable, prepare a sourced handoff and name the unresolved routing. Creating this handoff does not itself authorize dispatch.

## Next-Meeting Agenda or Partner Update

Lead with delivered outcomes, the remaining requests, and decisions that need the participants. Keep internal implementation history in linked detail. Consolidate partner questions and make each answer easy. Use the current project's acceptance rule; routine reassurance is not a new partner obligation.

## Compact Presentation

Apply `phone-size` and `sams-tree`. Use tiny trees with at most two displayed levels: actions or familiar groups, then supported subtasks. Keep the meeting title outside the counted levels. Avoid forced branches and long lines. The entire default chat response should fit one iPhone screen, not just its introduction. Keep full requirements in existing records and use direct source links sparingly. Do not create an overflow file or append a scrolling evidence report. For explicitly requested document edits, use supported disclosure and preserve the underlying requirements. Report physical fit as unverified when the actual destination cannot be inspected.
